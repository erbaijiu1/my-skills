# Static Asset Migration

静态克隆站点常包含大量无效图片、缓存文件、重复脚本和历史页面副本。迁移时应优先提纯在用资源，而不是把整个克隆目录直接并入前端或后端项目。

## 目标

- 只保留真实被页面、组件、种子数据或模板引用的资源。
- 将大体积静态文件与应用源码适度隔离，避免仓库和构建产物膨胀。
- 建立稳定、可追踪的路径映射，便于后续替换或补图。

## 推荐流程

1. 先扫描 HTML、CSS、JS、种子数据和模板中的资源引用。
2. 修复相对路径、失效路径和重复路径，必要时统一映射到新的静态资源前缀。
3. 若资源量很大，编写脚本提取“实际被引用”的文件，不要直接复制整个 data、assets 或 cache 目录。
4. 对少量但难以通过静态分析完整提取的目录，可以整体保留，但要说明原因。
5. 在部署层为这些资源选择合适的托管位置，例如前端 public、独立静态目录或网关直接托管。

## 部署注意点

- 如果静态资源目录独立于前端构建产物，确认网关或静态服务器已正确映射。
- 如果后端种子数据中保存了旧路径，修改代码后还要确认数据库或持久卷中的旧数据是否需要清理或重建。
- 不要让 Nuxt 构建输出或 FastAPI StaticFiles 背负明显不必要的大规模静态文件。

## 常见错误

- 把整个克隆出来的 data 目录直接放进 public。
- 只修复了源码路径，但没有处理数据库或持久卷里的旧路径。
- 漏掉内联样式、内联脚本或模板字符串里拼接出来的资源地址。
- 清理资源时误删仍被页面、脚本或模板依赖的素材。
